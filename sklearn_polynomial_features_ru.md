Источник: [официальная документация scikit-learn: `sklearn.preprocessing.PolynomialFeatures`](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.PolynomialFeatures.html)

https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.PolynomialFeatures.html

Этот файл создан как учебный русскоязычный конспект по странице документации. Он не является дословной копией всей страницы, а передаёт основные идеи, параметры, атрибуты, методы и практический смысл `PolynomialFeatures`.

## Кратко

`PolynomialFeatures` — это преобразователь из модуля `sklearn.preprocessing`, который создаёт новые признаки из исходных признаков.

Он добавляет:

- степени исходных признаков;
- произведения признаков друг на друга;
- при необходимости столбец из единиц, который играет роль свободного члена.

Например, если исходные признаки:

```text
[a, b]
```

то при степени `degree=2` можно получить:

```text
[1, a, b, a^2, a*b, b^2]
```

В проекте ML1 это используется в части **4. Creating Features**, где требуется применить:

```python
PolynomialFeatures(degree=10)
```

к обучающим и тестовым данным.

## Зачем нужны полиномиальные признаки

Линейная регрессия сама по себе строит линейную зависимость:

```text
y = w0 + w1*x1 + w2*x2
```

Такая модель может плохо описывать нелинейные связи. Например, цена квартиры может расти не строго линейно при увеличении числа комнат.

Если добавить полиномиальные признаки, линейная модель всё ещё остаётся линейной по коэффициентам, но получает более богатое описание данных:

```text
y = w0 + w1*x1 + w2*x2 + w3*x1^2 + w4*x1*x2 + w5*x2^2
```

Так линейная регрессия может учитывать:

- квадраты признаков;
- кубы признаков;
- взаимодействия признаков;
- более сложные зависимости.

## Основной импорт

```python
from sklearn.preprocessing import PolynomialFeatures
```

Обычно `PolynomialFeatures` используют перед линейной моделью:

```python
from sklearn.linear_model import LinearRegression
from sklearn.preprocessing import PolynomialFeatures

poly = PolynomialFeatures(degree=2)
X_poly = poly.fit_transform(X)

model = LinearRegression()
model.fit(X_poly, y)
```

## Сигнатура класса

```python
PolynomialFeatures(
    degree=2,
    *,
    interaction_only=False,
    include_bias=True,
    order="C"
)
```

Звёздочка `*` означает, что параметры после неё нужно передавать по имени.

Например:

```python
PolynomialFeatures(2, include_bias=False)
```

а не так:

```python
PolynomialFeatures(2, False)
```

## Параметры

## `degree`

Тип:

```text
int или tuple(min_degree, max_degree)
```

Значение по умолчанию:

```text
2
```

`degree` задаёт максимальную степень создаваемых полиномиальных признаков.

Если указать:

```python
PolynomialFeatures(degree=2)
```

то будут созданы признаки до второй степени.

Если исходные признаки:

```text
x1, x2
```

то результат может включать:

```text
1, x1, x2, x1^2, x1*x2, x2^2
```

Если указать:

```python
PolynomialFeatures(degree=3)
```

то добавятся признаки до третьей степени:

```text
x1^3, x1^2*x2, x1*x2^2, x2^3
```

В новых версиях scikit-learn `degree` может быть не только числом, но и кортежем:

```python
PolynomialFeatures(degree=(2, 3))
```

Это означает: создать признаки от степени 2 до степени 3.

### Важное замечание про степень

Чем выше `degree`, тем больше новых признаков появляется.

Это может привести к двум проблемам:

1. вычисления станут тяжелее;
2. модель может переобучиться.

**Переобучение** — ситуация, когда модель слишком хорошо подстроилась под обучающие данные, но плохо работает на новых данных.

## `interaction_only`

Тип:

```text
bool
```

Значение по умолчанию:

```text
False
```

Если:

```python
interaction_only=False
```

то создаются и степени признаков, и их взаимодействия:

```text
x1, x2, x1^2, x1*x2, x2^2
```

Если:

```python
interaction_only=True
```

то создаются только взаимодействия разных признаков, а степени одного и того же признака исключаются.

Например, будут включены:

```text
x1
x2
x1*x2
```

Но не будут включены:

```text
x1^2
x2^2
x1^2*x2
```

### Когда полезен `interaction_only=True`

Этот режим полезен, если нас интересует именно совместное влияние разных признаков, но мы не хотим добавлять квадраты и более высокие степени каждого отдельного признака.

Например, можно проверить, влияет ли сочетание `bathrooms * bedrooms` на цену сильнее, чем каждый признак отдельно.

## `include_bias`

Тип:

```text
bool
```

Значение по умолчанию:

```text
True
```

Если:

```python
include_bias=True
```

то в результат добавляется столбец из единиц:

```text
1
```

Этот столбец соответствует полиномиальному члену степени 0.

В линейной модели он играет роль свободного члена, или intercept.

### Что такое intercept

**Intercept**, или свободный член, — это значение предсказания модели, когда все признаки равны нулю.

В формуле:

```text
y = w0 + w1*x1 + w2*x2
```

`w0` — это intercept.

### Что выбрать в проекте ML1

В нашем ноутбуке используется:

```python
PolynomialFeatures(degree=10, include_bias=False)
```

Это удобно, потому что `LinearRegression` в sklearn по умолчанию сама добавляет свободный член через параметр `fit_intercept=True`.

Если одновременно оставить `include_bias=True` и `fit_intercept=True`, в данных может появиться лишний дублирующий столбец единиц. Обычно это не критично, но чище использовать `include_bias=False`.

## `order`

Тип:

```text
"C" или "F"
```

Значение по умолчанию:

```text
"C"
```

Этот параметр задаёт порядок хранения данных в плотном массиве.

`"C"` — C-style order, построчный порядок.

`"F"` — Fortran-style order, поколоночный порядок.

В документации указано, что `"F"` может быстрее создавать признаки, но иногда последующие модели могут работать медленнее.

Для обычной учебной задачи лучше оставить значение по умолчанию:

```python
order="C"
```

## Основные атрибуты после `fit`

Атрибуты появляются после вызова:

```python
poly.fit(X)
```

или:

```python
poly.fit_transform(X)
```

## `powers_`

`powers_` показывает, в какие степени возводятся исходные признаки для каждого выходного признака.

Например, если есть два признака:

```text
x1, x2
```

то для `degree=2` возможна такая логика:

| Выходной признак | Степень `x1` | Степень `x2` |
| --- | ---: | ---: |
| `1` | 0 | 0 |
| `x1` | 1 | 0 |
| `x2` | 0 | 1 |
| `x1^2` | 2 | 0 |
| `x1*x2` | 1 | 1 |
| `x2^2` | 0 | 2 |

## `n_features_in_`

Количество исходных признаков, которые преобразователь увидел при обучении.

Если мы передали:

```python
X = filtered_data[["bathrooms", "bedrooms"]]
```

то:

```text
n_features_in_ = 2
```

## `feature_names_in_`

Имена исходных признаков, если они были переданы как строки.

Например:

```text
["bathrooms", "bedrooms"]
```

## `n_output_features_`

Количество признаков после преобразования.

В проекте ML1 при двух исходных признаках и `degree=10` получается:

```text
65
```

То есть из двух столбцов `bathrooms` и `bedrooms` создаётся 65 полиномиальных признаков.

## Основные методы

## `fit(X, y=None)`

Метод `fit` подготавливает преобразователь.

Для `PolynomialFeatures` это означает: определить, сколько будет выходных признаков и какие комбинации степеней нужно создать.

`y` не используется и нужен только для совместимости с общим API sklearn.

## `transform(X)`

Метод `transform` применяет уже подготовленное преобразование к данным.

Пример:

```python
poly.fit(X_train)
X_train_poly = poly.transform(X_train)
X_test_poly = poly.transform(X_test)
```

## `fit_transform(X, y=None)`

Метод `fit_transform` сначала выполняет `fit`, затем сразу `transform`.

Обычно для обучающей выборки пишут:

```python
X_train_poly = poly.fit_transform(X_train)
```

А для тестовой:

```python
X_test_poly = poly.transform(X_test)
```

### Почему нельзя делать `fit_transform` на test

Тестовая выборка должна имитировать новые данные, которых модель не видела.

Если обучать преобразователь на test, это может привести к утечке данных.

**Data leakage**, или утечка данных, — ситуация, когда информация из тестовой выборки влияет на обучение. Из-за этого метрики могут стать слишком оптимистичными.

Для `PolynomialFeatures` риск утечки меньше, чем для стандартизации или кодирования категорий, потому что преобразователь не считает средние значения или частоты. Но правильная привычка в sklearn такая:

```python
fit_transform на train
transform на test
```

## `get_feature_names_out(input_features=None)`

Метод возвращает имена созданных признаков.

Пример:

```python
poly = PolynomialFeatures(degree=2, include_bias=False)
X_poly = poly.fit_transform(X)
poly.get_feature_names_out(["bathrooms", "bedrooms"])
```

Возможный результат:

```text
["bathrooms", "bedrooms", "bathrooms^2", "bathrooms bedrooms", "bedrooms^2"]
```

Это удобно, если нужно понять, какие именно признаки были созданы.

## Пример на маленьких данных

Пусть есть таблица с двумя признаками:

```python
import numpy as np
from sklearn.preprocessing import PolynomialFeatures

X = np.array([
    [0, 1],
    [2, 3],
    [4, 5],
])
```

Создадим признаки степени 2:

```python
poly = PolynomialFeatures(degree=2)
X_poly = poly.fit_transform(X)
print(X_poly)
```

Результат:

```text
[[ 1.  0.  1.  0.  0.  1.]
 [ 1.  2.  3.  4.  6.  9.]
 [ 1.  4.  5. 16. 20. 25.]]
```

Как читать первую строку:

Исходная строка:

```text
[0, 1]
```

Полиномиальные признаки:

```text
[1, x1, x2, x1^2, x1*x2, x2^2]
```

Подставляем:

```text
[1, 0, 1, 0^2, 0*1, 1^2] = [1, 0, 1, 0, 0, 1]
```

## Пример с `interaction_only=True`

```python
poly = PolynomialFeatures(degree=2, interaction_only=True)
X_poly = poly.fit_transform(X)
print(X_poly)
```

В этом режиме для двух признаков получаем:

```text
[1, x1, x2, x1*x2]
```

Квадраты `x1^2` и `x2^2` не создаются.

## Применение в ML1

В проекте ML1 мы работаем с признаками:

```python
X = filtered_data[["bathrooms", "bedrooms"]]
y = filtered_data["price"]
```

Затем делим данные:

```python
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.25,
    random_state=21,
)
```

После этого создаём полиномиальные признаки:

```python
poly = PolynomialFeatures(degree=10, include_bias=False)

X_train_poly = poly.fit_transform(X_train)
X_test_poly = poly.transform(X_test)
```

Зачем это нужно:

- задание требует применить `PolynomialFeatures` со степенью 10;
- линейная регрессия получает больше признаков;
- модель может учитывать нелинейные зависимости между `bathrooms`, `bedrooms` и `price`.

## Почему степень 10 может быть опасной

Высокая степень создаёт много признаков.

Для двух исходных признаков это ещё терпимо:

```text
2 признака -> 65 признаков после PolynomialFeatures(degree=10, include_bias=False)
```

Но если исходных признаков будет много, число новых признаков вырастет очень быстро.

Проблемы высокой степени:

- больше памяти;
- больше времени на обучение;
- больше риск переобучения;
- коэффициенты линейной модели могут стать нестабильными;
- модель может слишком сильно реагировать на редкие сочетания признаков.

## Практический совет

Для учебного задания мы используем `degree=10`, потому что так сказано в условии.

В реальном проекте степень обычно подбирают по качеству на validation/test:

```python
for degree in [1, 2, 3, 4, 5]:
    ...
```

И выбирают степень, которая даёт лучшее качество на новых данных, а не только на train.

## Связь с линейной регрессией

`PolynomialFeatures` сам по себе не является моделью.

Он не предсказывает `price`.

Он только преобразует таблицу признаков.

Предсказание делает модель, например:

```python
LinearRegression()
```

Типичный pipeline выглядит так:

```text
исходные признаки -> PolynomialFeatures -> LinearRegression -> prediction
```

В sklearn это часто оформляют через `Pipeline`, но в ML1 код написан по шагам, чтобы было проще понять процесс.

## Мини-словарь

**Transformer** — объект sklearn, который преобразует данные. `PolynomialFeatures` является transformer.

**Estimator** — объект sklearn, у которого есть метод `fit`.

**Feature matrix** — матрица признаков `X`.

**Output features** — признаки после преобразования.

**Interaction feature** — признак-взаимодействие, например `bathrooms * bedrooms`.

**Bias column** — столбец из единиц, который может играть роль свободного члена.

**Dense array** — обычный плотный массив, где хранятся все значения.

**Sparse matrix** — разреженная матрица, эффективная для данных с большим количеством нулей.

**Overfitting** — переобучение, когда модель хорошо работает на train, но плохо на test.

## Короткий вывод

`PolynomialFeatures` нужен для автоматического создания полиномиальных признаков.

В ML1 он используется, чтобы:

- выполнить пункт задания про создание признаков;
- расширить признаки `bathrooms` и `bedrooms`;
- обучить линейную регрессию на более богатом признаковом пространстве;
- показать, что простая линейная модель может учитывать нелинейные зависимости через предварительное преобразование данных.

Главная осторожность: чем выше степень и чем больше исходных признаков, тем быстрее растёт число новых признаков и тем выше риск переобучения.
