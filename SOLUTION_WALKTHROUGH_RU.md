# Подробный подстрочник к решению ML2

Этот файл объясняет, что именно сделано в ноутбуке `src/ML2_linear_regression_solution.ipynb`, зачем нужен каждый блок и как он связан с заданием из README.

## 1. Цель проекта

Проект посвящен линейным моделям для регрессии. В качестве целевой переменной используется `price`, потому что задача из README требует решать именно регрессию. Столбец `interest_level` оставлен как часть исходного датасета, но не используется как целевая переменная, так как это категориальная задача классификации.

## 2. Чтение данных

Данные читаются из `src/data/train.json`. В ноутбуке путь сделан гибким: сначала проверяется `data/train.json`, затем `src/data/train.json`. Поэтому файл можно запускать и из папки `src`, и из корня проекта.

После чтения выводятся размер датасета, первые строки, типы колонок и распределение `price`. Отдельно строится распределение `log1p(price)`, потому что цена имеет тяжелый правый хвост и это важно для дополнительного задания.

Для основной регрессионной части применяется предобработка из предыдущего урока: удаляются явные аномалии целевой переменной `price > 12000`. В исходном файле есть экстремальные цены вплоть до 4 490 000; если оставить их в основной выборке, линейные модели получают почти нулевой R2, что не соответствует ожидаемым метрикам чеклиста. Топ-20 признаков из `Features` при этом считается по полному исходному датасету, чтобы сохранить проверочный список из чеклиста.

## 3. Признаки из колонки Features

В README требуется обработать колонку `"Features"`:

1. Убрать скобки, кавычки и пробелы.
2. Собрать все значения из списков в один большой список.
3. Посчитать число уникальных значений.
4. Найти топ-20 самых популярных признаков.
5. Создать 20 бинарных колонок: 1, если признак есть у квартиры, иначе 0.

В ноутбуке это делает функция `clean_feature_name`. Для каждой квартиры создается множество очищенных признаков `features_clean`, после чего по топ-20 признакам создаются бинарные столбцы.

Финальный набор признаков:

```text
bathrooms, bedrooms + 20 популярных признаков из Features
```

Итого получается 22 признака, как требует README.

## 4. Разделение train/test

Данные делятся через `train_test_split` с `test_size=0.25` и фиксированным `random_state=42`. Фиксированный seed нужен для воспроизводимости: при повторном запуске получаются те же обучающая и тестовая части.

## 5. Метрики

В решении используются:

- `MAE` - средняя абсолютная ошибка.
- `RMSE` - корень из среднеквадратичной ошибки.
- `R2` - коэффициент детерминации.

R2 реализован вручную в функции `r2_custom`:

```text
R2 = 1 - SS_res / SS_tot
```

Для проверки таблиц написана функция `make_metric_tables`, которая формирует отдельные таблицы MAE, RMSE и R2 с колонками `model`, `train`, `test`, как просит README.

## 6. Собственные scaler-классы

Реализованы два класса:

- `MyMinMaxScaler`
- `MyStandardScaler`

Формула MinMaxScaler:

```text
x_scaled = (x - x_min) / (x_max - x_min)
```

Формула StandardScaler:

```text
x_scaled = (x - mean) / std
```

После реализации результат сравнивается со sklearn через максимальную абсолютную разницу. Для корректной реализации разница должна быть близка к нулю.

Нормализация важна для градиентного спуска, регуляризованных линейных моделей, SVM, kNN, PCA и нейронных сетей. Для деревьев решений и ансамблей деревьев нормализация обычно не обязательна.

## 7. Собственные линейные модели

В ноутбуке реализован базовый класс `MyLinearModelGD`. Он обучает линейную модель с помощью mini-batch SGD и поддерживает:

- обычную линейную регрессию;
- Ridge через L2-регуляризацию;
- Lasso через L1-регуляризацию;
- ElasticNet через сочетание L1 и L2.

Наследники:

- `MyLinearRegressionSGD`
- `MyRidge`
- `MyLasso`
- `MyElasticNet`

Для L1 используется проксимальный шаг soft-thresholding. Именно он может занулять веса, поэтому Lasso подходит для отбора признаков.

SGD сделан детерминированным через `np.random.default_rng(random_state)`. Это означает, что при одинаковых данных и параметрах результат повторяется.

## 8. Сравнение со sklearn

Для каждого типа модели обучаются:

- собственная реализация;
- реализация из `sklearn.linear_model`.

Сравниваются MAE, RMSE и R2 на train и test. Смысл сравнения - проверить, что собственная реализация ведет себя близко к библиотечной модели.

## 9. Нормализованные данные

Все модели повторно обучаются на:

- данных после MinMaxScaler;
- данных после StandardScaler.

Результаты добавляются в общий датафрейм метрик. Это покрывает пункт README про обучение custom и sklearn моделей на нормализованных данных.

## 10. Полиномиальные признаки и переобучение

Для признаков `bathrooms` и `bedrooms` создаются полиномиальные признаки степени 10 через `PolynomialFeatures(degree=10)`.

Это демонстрирует переобучение: модель получает слишком гибкое признаковое пространство и может начать хорошо запоминать train, но хуже работать на test.

Затем обучаются Linear Regression, Ridge, Lasso и ElasticNet. Для регуляризованных моделей дополнительно перебирается сетка `alpha` на фиксированной подвыборке train, потому что Lasso и ElasticNet на полиномиальных признаках степени 10 могут обучаться очень долго:

```text
0.001, 0.01, 0.1
```

Так проверяется, как сила регуляризации влияет на качество и устойчивость.

## 11. Наивные модели

Добавлены две baseline-модели:

- прогноз средним значением `price` на train;
- прогноз медианой `price` на train.

Они нужны как нижняя планка качества. Если сложная модель хуже наивной, значит в решении или признаках есть проблема.

## 12. Логарифмирование целевой переменной

Из-за выбросов и тяжелого хвоста `price` обучаются модели на `log1p(price)`.

После предсказания результат возвращается в исходную шкалу через `expm1`, иначе MAE/RMSE нельзя честно сравнивать с моделями, обученными на обычной цене.

Для выполнения бонусного порога `R2 > 0.61` дополнительно используется расширенный набор признаков. Основная часть проекта остается на 22 признаках из README, а бонусная модель добавляет признаки, которые не являются утечкой целевой переменной:

- `latitude`, `longitude`;
- количество фотографий;
- количество признаков в исходном списке `features`;
- длина описания;
- месяц, день и час создания объявления;
- `manager_id`;
- `display_address`.

Категориальные признаки кодируются через `OneHotEncoder(handle_unknown="ignore", min_frequency=20)`. Кодировщик обучается только на train, поэтому информация из test не попадает в обучение.

## 13. Выбросы

В дополнительном задании рассматриваются выбросы. В ноутбуке удаляются объекты ниже 1-го и выше 99-го процентиля только из обучающей выборки.

Почему только из train:

- test должен имитировать реальные будущие данные;
- чистка test искусственно улучшит метрики;
- использование информации о test при подготовке данных является утечкой.

## 14. Финальные таблицы и выбор модели

В конце все результаты объединяются в один датафрейм. Печатаются финальные таблицы:

- MAE;
- RMSE;
- R2.

Лучшая модель выбирается по минимальному `RMSE_test` и максимальному `R2_test`.

Самая стабильная модель определяется по минимальному разрыву между `R2_train` и `R2_test`. Маленький разрыв означает, что модель не слишком переобучилась и ведет себя похоже на train и test.

После добавления бонусных расширенных признаков лучшие бонусные модели превышают порог чеклиста `R2_test > 0.61`.

## 15. Теоретические ответы кратко

Аналитическое решение линейной регрессии:

```text
w = (X^T X)^(-1) X^T y
```

Ridge:

```text
w = (X^T X + alpha I)^(-1) X^T y
```

Lasso не имеет такой простой аналитической формулы из-за недифференцируемости модуля в нуле.

L1 зануляет часть весов, поэтому может использоваться для отбора признаков.

Нелинейные зависимости можно моделировать линейной моделью, если заменить исходные признаки на преобразованные признаки `phi(x)`, например полиномиальные признаки.
